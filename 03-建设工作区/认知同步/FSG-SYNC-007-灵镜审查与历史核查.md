### 1.4 建议优化

**（1）「建议阅读顺序」有元问题：读者正在读的这份文件没被列进去。**

现在写的是：

> 1. 会话锚点与协作流程
> 2. 决议待办
> 3. 基础建设路线图

一个新人打开这个目录，第一眼看到的是 README，然后被指去看第 1 项。但 README 本身的内容（本目录是什么、不构成规范、权限提醒）恰恰应该最先被读到。

> 1. 本页（目录说明与边界提醒）
> 2. 会话锚点与协作流程（怎么工作）
> 3. 决议待办（现在卡在哪）
> 4. 基础建设路线图（往哪走）

理由：先知道「这里的东西不算规范」，再知道「怎么做」，最后才是「做什么」。现在把「做什么」放最后是对的，但「不算规范」这层提醒被排在了流程之后。

**（3）缺失一项导航：文件编号与决议编号的对照。**

`00-决议待办.md` 是 FSG-WORK-001，`01-基础建设路线图.md` 是 FSG-WORK-002，`02-会话锚点与协作流程.md` 是 FSG-WORK-003，但文件名上的数字和编号上的数字**不对应**（文件名 00/01/02，编号 001/002/003，勉强对齐；但以后加文件就会错位）。

README 里没提这层关系。建议加一句：「本目录文件同时具有文件名序号和 FSG-WORK 编号两套标识，引用时以 FSG-WORK 编号为准。」

### 1.5 是否有句子无意中创设了规则

这是你问的第三点，我认真查了。**有，但性质轻微，而且我认为不该删。**

README 开头写：

> **目录说明，不是正式规范，不创设成员义务、治理权或制度决策权。**

但正文里有这几句是**规范性表述**：

| 原文 | 性质 |
|---|---|
| 「各文件应以自身标注的版本和状态为准」 | 规定了判定标准 |
| 「涉及具体任务时，应重新核对相关文件」 | 创设了一个动作义务 |
| 「不因存放于此目录而自动成为正式规范」 | 规定了什么算规范 |
| 「尚未解决的问题继续保留在决议待办中」 | 规定了处理路径 |
| 「未获授权的事项不因工作推进而自动获得批准」 | 规定了授权边界 |

**这不是缺陷，是这个文件的真实身份没被说准。**

它自称「不是正式规范」，但它确实在做规范性的工作——它在规定这个目录里什么东西算什么。这是**工作约定（working convention）**，不是制度规范（institutional rule）。

我的建议不是删句子，而是**把身份说准**。加一句：

> 本页包含的约定属于工作约定，可由创建者随时调整，不需要走制度修订程序；它与制度规范的区别在于：制度规范约束全体成员的行为，工作约定只约束本目录的使用方式。

这样既不假装自己没规矩，也不假装自己有制度效力。

## 3. FSG-D-013 四点边界评审

### 3.1 总体判断

**四点比我的三句好，我撤回三句，以你的四点为讨论基础。**

好的地方：你把「网站定位」从「只呈现认知」扩到了五类内容，这个修正是对的——我原来的说法确实太窄，把知识成果和研究资料挤出去了。

下面的意见都是在这个基础上提的。

### 3.2 逐条评估

**一、制度来源唯一** —— 方向对，但依赖一个未定义的词。

原文：「蜉熵阁**经正式确认**的共同制度、决议及规范……」

「正式确认」是什么，现在没有定义。这正是 FSG-D-001（初始生效机制）卡住的地方。

所以这一条现在写下去，会引用一个空概念。两个处理方式：

- 加一句「『正式确认』的含义，以 FSG-D-001 决议为准」，先把坑标出来；
- 或者干脆先不写「经正式确认」，写「以章程与规范仓库中的有效文件为权威来源」，把「有效」交给状态标记体系（草案/讨论稿/已通过待生效/现行有效/已修订/已废止/历史归档）去承担。

我倾向第二种：**状态标记已经存在，不需要再发明一个「正式确认」**。

**二、网站定位** —— 五类内容，建议补一个兜底。

五类是：成员认知、身份档案、知识成果、研究资料、经授权公开的内容。

缺的是：公告、活动记录、历史归档、对外介绍。这些都不属于前五类，但网站肯定要放。

建议改成「……及**其他经授权公开的内容**」，用兜底把开放列表收住。

**三、规范引用** —— 好，但没说谁负责修正。

原文：「若网站展示内容与规范仓库中的有效文本不一致，以……为准，**并应修正展示内容**。」

「应修正」没主语、没时限。建议补：「由网站维护者在下一次更新时修正；期间应在不一致页面上加注说明。」

这不是抠字眼——没有责任人的义务条款，等于没有。

**四、内容状态区分** —— 最好的一条，但需要标注机制。

原文：「网站上的个人观点、研究假说、建议、草案和共同制度必须明确区分，**不因公开展示或被多个成员引用而自动成为共同规则**。」

后半句是这个体系里最关键的防线之一。但它需要在页面上有**可操作的标注方式**，否则只是理念。

我建议一个最小标注法，四类各一个标记：

| 类型 | 标记 | 含义 |
|---|---|---|
| 共同制度 | 带 FSG 文件号 + 版本 + 状态 | 引用自规范库，不得改写 |
| 成员个人规范 | 署提出者 + 适用范围 | 只对该成员或该项目有效 |
| 研究假说 / 建议 | 署提出者 + 「未经验证」 | 可被引用，不可被当作依据 |
| 工作约定 | 署「工作约定」+ 调整方式 | 可随时改，不走制度程序 |

### 3.3 你问的三个风险

**风险一：「制度来源唯一」会不会压制成员个人表达或研究独立性？**

**不会——前提是加一句限定。**

区分两种东西：

- **共同制度**：约束全体成员行为 → 只能来自规范库
- **个人立场**：只代表提出者 → 任何地方都能说，包括网站

「制度来源唯一」管的是前者。如果不管后者，它就变成了「只有规范库里的想法才算数」，那才是压制。

建议加一句：「成员个人观点、研究方法、项目约定不属于共同制度，不受本条限制；但发表时须署明提出者，不得以共同体名义表达。」

**风险二：网站能否保留成员自己的个人规范？怎么标注适用范围？**

能，而且应该保留。

这是「成员独立性」的落地方式之一。我的建议：

- 网站可以设「成员个人工作法」一类栏目
- 每篇必须写清三件事：**谁提的、管什么范围、跟共同制度冲突时以谁为准**
- 默认规则：**个人规范与共同制度冲突时，共同制度优先；个人规范内部，提出者优先**

第三条特别重要。否则将来会出现「我的工作法说可以，章程说不可以」的扯皮。

**风险三：「有效文件」与「决议记录」的优先关系？**

**决议记录优先。**

理由是根本性的：**制度的效力来自「做过一次确认这个行为」，不来自「文件里写着什么」。**

文件是载体，决议是行为。文件可以改、可以覆盖（4-20 那次就是被覆盖了），但决议记录如果有独立存档，就改不掉。

所以优先级：

```
决议记录 > 规范文件正文 > 状态标记 > 网站展示
```

如果决议记录说「某条已通过」，但文件正文没更新 → 以决议为准，文件标记为「待同步」。
如果文件写着「现行有效」，但找不到对应决议 → 标记为「状态存疑」，不算有效。

**这一条建议直接写进 D-013 的第四点或单独成第五点。**
